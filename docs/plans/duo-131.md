# Duo 1.3.1 Implementation Plan: Explore with the place, two-pane Profile

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task, one task at a time (one builder, its review, then the next; no parallel worktrees). Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** Tasks 0 to 6 built and reviewed on `1.3.1` (2026-11-17, head `5f2d282`); Task 7, the simulator check, is on hold until the owner says go. 1.3.0 went live on 2026-11-17. The work still happens on its own branch, `1.3.1`, so `1.3` stays what the store has.

**Goal:** On the open iPhone Duo only, Explore shows the list with the chosen place beside it, and Profile shows a right pane (guide link, Saved Places, Photo credits, or sign-in for a guest). Every iPhone, the folded Duo and Split View stay exactly as 1.3.0 ships them.

**Architecture:** Same switch as 1.3: `useWide()` (window ≥ 600 pt) from `@blacksands/ui`, same components on every width, null slots, no `key` change on the breakpoint. The place screen's body moves out of its route file into a component that can also render as a pane. Saved Places, Photo credits and the sign-in form get the same treatment: the body becomes a component, the route keeps its top bar. 1.3's wide Explore (the 200 pt side band with photo cards) and 1.3's wide Profile (two columns of settings) are replaced by these layouts.

**Tech Stack:** Expo SDK 58, React Native 0.88, expo-router 58, Jest (jest-expo) with @testing-library/react-native, `test/wideMock.js` (`__setWide(true, { width, height })`), engine `@blacksands/ui` 0.7.3 and `@blacksands/components` 0.13.1. No engine change is planned.

**Spec:** the "Picked values" section below, and the drawings on the [1.3.1 mocks page](https://claude.ai/artifact/6NR3pWF54NL36rgoNvfZhX): Explore round 5 ("explace-r5b"), Profile round 5 for the guide link and the guest, Profile round 2 for Saved Places and Photo credits. Task 0 copies the picked values into `docs/plans/design-sweep.md` under "## Wide".

Simulator checks go to the `simulator` channel only: `npx eas-cli@latest update --channel simulator --platform ios --environment production`, run by the owner or with the owner's go.

- **Breakpoint:** wide is 600 pt or more. Folded (466), Split View (469) and every iPhone are the phone layout.
- **Nothing moves on a phone.** Every existing phone test passes unchanged. A test file may gain wide tests; a phone assertion may only change if the task says so.
- **Same components on every width.** Only styles and arrangement switch. Folding mid-screen keeps state, scroll position and open sheets.
- **Engine first.** If a piece needs an engine change, stop and report: the owner publishes engine packages, and this shell can't install them.
- **Words on screen:** Trip/Trips, place, Profile. No new copy except what "Picked values" gives.
- **Light and dark:** colours from `tokens.colors` through `pair()`. Text no smaller than the phone's; contrast at least 4.5:1.
- **Status bar:** both screens keep a white top on wide, so the dark status bar.
- **Shell:** PowerShell for npm, npx and eas.

## Review Focus

1. **Tour targets registered twice.** Tab screens stay mounted, so with a place pane inside Explore and the place route also mounted, `placeAdd` and `placeSave` could register from both. The pane never registers tour targets. Pinned in Task 1.
2. **Folding mid-use.** Wide to phone on Explore: the list stays where it was scrolled, the chosen place is remembered, nothing navigates. Phone to wide: the pane shows the remembered place, or the first row. On Profile: an open Saved Places pane folds to the plain Profile, and a download or dialog in the left column survives. Pinned in Tasks 2 and 5.
3. **The chosen place leaves the list.** Changing town, category or search can remove the chosen place from the rows. The pane then shows the first row; with no rows it is empty and the list's own empty message shows. Pinned in Task 2.
4. **Guest and empty states.** A guest's Explore pane still asks for sign-in on Save, Review and Add to Trip. A guest's Profile shows the sign-in card and never the Saved Places pane. Saved Places with nothing saved shows its empty state in the pane. Pinned in Tasks 1, 4 and 5.
5. **Signing in from the card.** After sign-in the Profile becomes the signed-in layout with the guide card on the right; a failed sign-in shows its error inside the card; create-account mode (more fields) scrolls inside the card sideways and is never cut. Pinned in Task 4.

## Decisions made during the build (2026-11-17)

- **Folding closes the category pop-up.** It is wide only, as the guide's region picker is; the chosen category stays. Unfolding shows it again if it was open.
- **Folding closes a sheet opened from Explore's place pane** (the review sheet, Add to Trip, Create Trip). The pane's slot is empty on a phone, so its sheets go with it. A review draft is kept; a trip name or dates typed into Create Trip are lost. This is a stated exception to "folding keeps open sheets": keeping the pane running, hidden, on every phone would add background loading for all users. **The owner has been told and can ask for it to be changed.**
- **1.3's wide tests for the replaced layouts were replaced** by the new wide tests (Explore's side band and cards, Profile's two settings columns). No phone test was edited.
- **Row photos sit at x = 22,** 2 pt right of the head's 20 pt edge, as the round 5 drawing has them.
- **One phone change:** "View All Saved Places" now announces itself as a button to VoiceOver on every width, as the other rows on that screen do. Nothing visible changes.
- **Left as they are, Duo only:** after signing out with Saved Places open, signing back in reopens Saved Places; until a row is tapped the pane follows the first row, so it can change when the first location fix re-sorts the list; a guest's half-typed sign-in is lost on a fold or after opening Photo credits.
