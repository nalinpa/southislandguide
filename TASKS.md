### 1.1 — drive times and multi-day
**Built 2026-10-14 to 16; kept for history.** Drive times are generated per town (launch plan B1 to B3), `durationToSlots()` is gone, and the drive block (`components/itinerary/DriveBlock.tsx`) and the trip view with each day's towns (`components/itinerary/TripOverview.tsx`) are in. Since 2026-10-22 (fix-32, `f647e34` and `5a54c8f`): town-to-town times for all 41 towns (820 pairs), measured from a hub the owner picked for each town (`scripts/lib/areaCentres.js`, written to `assets/data/area-hubs.json`), and the 98 places far from their town's hub have their own times to every hub within 4 hours (`assets/data/far-place-minutes.json`). E.g. Te Anau to the Milford cruise is now 2 h. The notes below describe the state before all that. What's left is launch plan B4 to B6, only for drives that still read wrong on a phone.
- The transit matrix is `{}` today, so every leg defaults to 1 slot (30 min). Generate it with a port of `rotorua-guide/scripts/generate-transit-matrix.js`.
- **`durationToSlots()` caps at 4 slots (2 hours).** Fine for Christchurch; wrong the moment places are hours apart — Queenstown → Christchurch is ~12 slots. Uncap it before 1.2.
- **Distance Matrix cost is N².** 53 places ≈ 1,400 pairs ≈ $7. The whole island is ~$1,000+ without regional clustering (exact pairs within a region, hub-to-hub between regions).
- **The matrix is per area, not island-wide** (decided 2026-10-13). Two levels: place-to-place times only between places in the same `area`, and one drive time for each pair of areas, which is what the drive block shows. So Christchurch place → Christchurch place reads the area's own matrix, and Christchurch place → Dunedin place reads the Christchurch–Dunedin time. This removes the N² problem above: the place matrices grow with the size of each area (about 1,250 pairs, roughly $6, for the 96 places live today, against about 3,900 for one matrix), and the area table is three pairs today, few enough to enter by hand. Real place-to-place times inside an area are for later; flat 30 minutes stands until then (owner, 2026-10-13). Known roughness: one time per pair of areas means north Christchurch → south Dunedin reads the same as south Christchurch → north Dunedin. Cheapest correction, needing no new fields: scale the area-to-area time by the straight-line distance between the two actual places over the straight-line distance between the two area centres (`distanceMeters`, each area given one centre point), then round to the half hour. If places well off the main road still read wrong (a peninsula, say), add one optional per-place number of extra minutes for those only. Still to settle when building: the lookup takes two site ids and has to know each one's area, so either the generated file carries a site → area map or the callers pass it in.
- Day grid is 8am–10pm (28 slots); a long drive can eat most of a day. Start by rendering it as one tall transit block and see if that's usable before building anything structural.
- **Driving time as a block in the day view** (added 2026-10-13). **Not** the existing transit connector: `ItineraryDetailView.tsx` already draws the shared kit's `TransitBlock` (dashed line, train icon, "Transit 30 min") in the gap between two places, and that is a different thing. ## Tooling

- **Drive times:** `scripts/generate-drive-times.js areas|towns|far [--area <id>] [--apply]` — dry run by default (prints lookups and rough cost); `areas` is town-to-town and the hubs, `towns --area <id>` one town's in-town table, `far` the far-out places' own times. Needs `GOOGLE_MAPS_API_KEY`. **The month's free 10,000 lookups ran out 2026-10-21 and come back 1 Nov 2026**; until then every `--apply` is paid (US$5 per 1,000), whatever the dry run says.
- **Load places:** `scripts/upload-places.js` — dry run by default, `--apply` to write. Doc id = slug, so re-runs overwrite rather than duplicate. Refuses a key for any project other than `southislandguide`. Credentials via `GOOGLE_APPLICATION_CREDENTIALS` (the key stays in `enginev1/api/scripts/`, not copied here).
- **Admin fields:** the registry's `locationFields` for this app now match the JSON (14 fields, 9 categories, 10 regions, price incl. `Free`, image fields). Previous 8-field value is in the 2026-09-28 session log if a rollback is ever needed. `isPremium` is deliberately absent — ticking it would blank the place (see Commerce).
- **Firestore:** `firestore.rules` and `firestore.indexes.json` are in the repo; deploy with `npx firebase deploy --only firestore`.
